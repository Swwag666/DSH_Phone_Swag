Управляй сессиями [DeepSeek Harness](https://github.com/deepseek-ai) со своего телефона - с дивана, из метро, с другого конца страны. DSH Phone поднимает на твоём ПК локальный узел, телефон цепляется к нему через [Tailscale](https://tailscale.com), и всё: список проектов, живой чат с агентом, ответы на апрувы, фото с камеры, голосовые. Никакого чужого облака, никаких серверов-посредников, никаких утечек. Данные не покидают твою сеть.

> Пошаговая установка с проверкой каждого звена и траблшутингом - **[GUIDE.md](GUIDE.md)**.

## Подключение за 4 шага

1. **Сеть.** Поставь [Tailscale](https://tailscale.com/download) на ПК и на телефон, войди одним аккаунтом. Приложение само определит IP ПК (сеть `100.x.x.x`) и покажет его в дашборде.
2. **Узел.** Запусти DSH Phone - сервер на порту `8460` поднимется сам. Рядом с треем живёт иконка, окно закрывается туда же.
3. **QR.** В дашборде есть карточка «QR-подключение». Наведи на неё камеру телефона (iPhone) или Google Lens (Android), тапни по ссылке - вход выполнится сам, набирать 32 символа токена не нужно.
4. **PWA.** Жми «Поделиться → На экран Домой» - будет полноценное приложение-иконка.

> Камера не берёт? В той же карточке есть кнопка «скопировать ссылку», а обычный путь никуда не делся: открой `http://<твой-IP>:8460` и вставь токен из карточки «Ключ доступа».

> **Важно:** на ПК должен быть запущен DeepSeek Harness Desktop. Дверь к агенту - одна из двух: наш плагин [`dsh-phone-bridge`](dsh-phone/plugin/dsh-phone-bridge) (ставится один раз, поднимает собственный TCP-мост и не требует ни облака, ни учётки) либо плагин Agents Anywhere (вход в учётку AA тоже не нужен). Узел пробует наш мост первым, AA держит запасным; если не поднят ни один, остаётся HTTP-канал web-половины плагина.

## Что умеет

- **Полный чат с агентом** - история сессий, markdown-рендер с таблицами и код-блоками, подсветка синтаксиса, typewriter-стриминг ответа
- **Отправка хода, стоп, повторы** - сообщение в занятую сессию не теряется: узел держит очередь и доставит, как агент освободится
- **Апрувы и вопросы агента** - кнопки прямо на телефоне, пуш-уведомление когда нужен твой ответ
- **Смена модели и прав доступа** - каталог моделей прямо из чата
- **Создание новых сессий** - выбор рабочей папки (cwd) с автоподсказкой
- **Фото с камеры и файлы** - HEIC и гигантские снимки конвертируются в JPEG на телефоне, до 50 МБ на вложение
- **Голос** - диктовка (Web Speech) или голосовое сообщение в чат
- **Оффлайн-кэш** - история и список сессий живут в localStorage, чат открывается мгновенно даже при плохой связи
- **Экспорт** - диалог в Markdown или JSON, через системный шеринг или файл
- **Мульти-устройства** - каждому телефону свой токен, свой коннектор и своё окно агента в DSH
- **Общий черновик** - недописанное сообщение синхронизируется между телефоном и полем ввода DSH Desktop: начал на телефоне, продолжил за компьютером и наоборот. Приоритет у того, кто печатает прямо сейчас, своё эхо не применяется
- **Уведомления и непрочитанные** - бейджи, пуши о завершении хода, статистика (время хода, токены, оценка стоимости)
- **QR-подключение** - навёл камеру, телефон вошёл сам: токен лежит в hash-фрагменте ссылки и не уходит в логи узла
- **Автообновление** - дашборд сам проверяет GitHub Releases и ставит новую версию с прогрессом скачивания
- **Независимость от Agents Anywhere** - свой плагин поднимает мост прямо внутри DSH Desktop; AA остаётся запасным, а если не поднят ни один мост, телефон живёт через HTTP-канал web-половины плагина. Плагин один на всё: и мост, и синхронизация черновика

## Как это устроено

```
┌──────────────────────────── DSH Phone.exe ────────────────────────────┐
│                                                                        │
│  ┌──────────────┐   invoke (IPC)  ┌─────────────────────────────────┐ │
│  │ Окно (WebView)│ <────────────> │ Rust-ядро                        │ │
│  │ React + TS    │                │  конфиг · токены · устройства    │ │
│  └──────────────┘                 │  автостарт · tray · tailscale    │ │
│                                   └───────────────┬─────────────────┘ │
│                                                   │                    │
│                                   ┌───────────────▼─────────────────┐ │
│                                   │ axum-узел :8460                  │ │
│                                   │  PWA для телефона (вшита в exe)  │ │
│                                   │  API + long-poll события         │ │
│                                   │  whitelist RPC · allowlist IP    │ │
│                                   └───────────────┬─────────────────┘ │
└───────────────────────────────────────────────────┼────────────────────┘
                                                    │ JSON-RPC (TCP), запасной путь - HTTP
                                       ┌────────────▼────────────┐
                                       │ DeepSeek Harness Desktop │
                                       │ плагин dsh-phone-bridge  │
                                       │ запасной: Agents Anywhere│
                                       └─────────────────────────┘
                                                    │ Tailscale (100.x)
                                              ┌─────▼─────┐
                                              │  Телефон  │  PWA в браузере
                                              └───────────┘
```

Один exe ~13 МБ. PWA-клиент вшит в бинарник при сборке - Python-гейтвей и Rust-узел раздают один и тот же клиент. Каждый телефон = отдельный коннектор моста, поэтому DSH Desktop открывает для каждого своё окно агента.

## Безопасность

- **Токен на каждое устройство** - крипто-рандом, сравнение constant-time. Смена ключа мгновенно отваливает старый. Токен передаётся в заголовке `X-Dsh-Token` (плюс совместимый query-фолбэк).
- **RPC-whitelist** - телефон может дёргать только 18 проверенных методов (16 моста + 2 локальных draft-метода: `session.updateDraft` / `session.getDraft`, обрабатываются на самом узле и в мост не уходят). Никаких произвольных вызовов. (Фактический список - `RPC_WHITELIST` в `gateway.py` / `WHITELIST` в `server.rs`, тест фиксирует количество.)
- **IP-allowlist с CIDR** - белые списки адресов, кто в tailnet вообще достучится до узла. Пусто = все. Loopback всегда можно.
- **Узел слушает `0.0.0.0` из коробки** - это нужно для доступа из tailnet, но значит «доступен из каждой сети, к которой подключён ПК». Если `allowed_ips` пуст, узел при старте печатает предупреждение в консоль/лог. Заполни allowlist (например `100.64.0.0/10`) или поставь `listenHost` в конкретный адрес - узел честно биндится на него (Rust-версия читает `listen_host` из конфига, а не игнорирует его).
- **Опциональный TLS** - самоподписанный серт с SAN на tailnet-IP и sha256-отпечатком для пиннинга на телефоне.
- **Лимиты запросов** - тело до 80 МБ, заголовки до 100 строк / 64 КБ - одну «толстую» куку узел не положит. 10 неудачных попыток авторизации подряд = разрыв соединения (Python-гейтвей).
- **Staging самоочищается** - загруженные вложения больше не копятся вечно: узел раз в час подчищает файлы старше 7 дней (`stagingRetentionSecs` / `staging_retention_secs`, 0 = только ручная чистка).
- **Plain HTTP в tailnet - осознанный выбор.** Tailscale это WireGuard: трафик уже зашифрован между устройствами. TLS включается тумблером для параноиков (и для микрофона в Safari).

## Конфиг

`%APPDATA%\dsh-phone\config.json` (Python-гейтвей - рядом с `gateway.py`):

| Поле | Смысл |
|------|-------|
| `token` / `devices` | ключи устройств: основное + до 8 доп. телефонов |
| `listen_port` | порт HTTP-узла, по умолчанию `8460` |
| `tailscale_ip` | определяется сам, можно поправить руками |
| `allowed_ips` | белый список IP/CIDR |
| `staging_retention_secs` | срок жизни загруженных файлов в staging (по умолчанию 7 дней) |
| `tls_enabled` | TLS поверх tailnet |
| `start_hidden` | старт свёрнутым в трей |
| `plugin_bridge_endpoint_path` | файл моста нашего плагина (`~/.dsh/dsh-phone/bridge/endpoint.json`) - пробуется первым |
| `bridge_endpoint_path` | файл моста AA (`~/.dsh/agents-anywhere/bridge/endpoint.json`) - запасной |

## Python-гейтвей - лёгкий вариант

Не хочешь ставить exe - есть [чистый Python-узел](dsh-phone/), только стандартная библиотека, ноль зависимостей:

```bat
cd dsh-phone
run.bat        :: или: python gateway.py
```

Токен появится в консоли и в `config.json`. Телефон подключается точно так же. Подходит для тонких клиентов, серверов и compulsive-минималистов.

## Траблшутинг

- **«Мост отключён» / пусто** - DSH Desktop должен быть запущен и хотя бы одна дверь открыта: `~/.dsh/dsh-phone/bridge/endpoint.json` (наш плагин) или `~/.dsh/agents-anywhere/bridge/endpoint.json` (AA). Что реально видит узел, показывает `GET /api/health`: `bridgeChannel` (`tcp` / `plugin` / `none`), `bridgeEndpoint` (какой файл сработал) и `pluginBridge` (метрики HTTP-канала: очередь, rtt, возраст последнего пуша).
- **Телефон не видит узел** - запусти `tools/fix-firewall.bat` от администратора (правило для порта 8460), проверь что оба устройства в одном tailnet.
- **Связь отвалилась после включения/выключения WARP** - кнопка «Лечить связь» в конфиг-карточке: узел перевязывает сокеты tailscaled (`debug rebind` + `restun`).
- **После обновления приложения** - закрой и открой страницу на телефоне заново.

## Сборка из исходников

Нужно: Node 20+, pnpm, Rust stable (MSVC), VS Build Tools 2022 (C++).

```bash
cd dsh-phone-desktop
pnpm install
npx tauri build            # релиз: src-tauri/target/release/dsh-phone.exe + NSIS-сетап
npx tauri dev              # дев-режим с hot reload
```

> Собирай через `tauri build`, не голым `cargo build` - иначе фронтенд не вшьётся в бинарник.

В `tauri.conf.json` включён `createUpdaterArtifacts`, поэтому bundler ждёт ключ подписи. Для обычной сборки задай пустышки или возьми готовый скрипт:

```bash
scripts\build-release.cmd              # бандл без подписи апдейтера
scripts\build-release.cmd -Sign        # бандл + подпись (нужен ключ)
scripts\build-release.cmd -Sign -Latest # ещё и latest.example.json для локальной проверки
```

Скрипт сам гасит запущенный `dsh-phone.exe` (иначе линкер ловит `os error 5`), собирает фронтенд, бандл и раскладывает артефакты в `releases\`.

## Автообновление и релизы

Приложение проверяет `releases/latest/download/latest.json` в этом репозитории и при наличии новой версии предлагает «обновить и перезапустить» - с прогрессом скачивания в дашборде.

Релиз собирается сам: запушь таг `v*`, и `.github/workflows/release.yml` через `tauri-action` соберёт NSIS-сетап, подпишет апдейтер, положит в релиз `latest.json` и опубликует его. Релиз публикуется сразу (не черновиком) - у черновика адрес `/latest/download/` не работает, и автообновление ничего не увидит.

Перед первым запуском в репозиторий надо добавить два секрета (Settings → Secrets and variables → Actions):

| Секрет | Откуда взять |
|--------|--------------|
| `TAURI_SIGNING_PRIVATE_KEY` | содержимое `~/.dsh-phone-updater/dsh-phone-updater.key` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | содержимое `~/.dsh-phone-updater/password.txt` |

Ключ генерится один раз и **никогда не коммитится** - он лежит в профиле пользователя:

```bash
npx tauri signer generate -w ~/.dsh-phone-updater/dsh-phone-updater.key
```

> Потеряешь ключ - подписывать обновления станет нечем, и поставленные версии перестанут обновляться. Храни копию вне машины.

Порядок выпуска версии: поднять `version` в `dsh-phone-desktop/src-tauri/tauri.conf.json`, `Cargo.toml` и `package.json` (плюс `dsh-phone/mobile/package.json` и `dsh-phone/plugin/dsh-phone-bridge/package.json`), обновить бейдж в начале README, **вместе с этим** пересобрать `releases/` и `latest.json` (нужен ключ подписи), закоммитить, затем `git tag v<версия> && git push origin v<версия>` — CI соберёт артефакты сам. Поднимать версию в отрыве от артефактов нельзя: тесты `updater_release` проверяют, что версия в `tauri.conf.json`, в `releases/latest.example.json` и в trusted-comment подписи совпадает, иначе апдейтер на телефонах отвергнет обновление.

> Подпись апдейтера (minisign) - это не код-сининг: SmartScreen по-прежнему будет ругаться на отсутствие сертификата. Она защищает другое - гарантирует, что обновление приехало от тебя, а не от того, кто подменил файл на диске или в канале доставки.

## Тесты

```bash
cd dsh-phone && python -m unittest -v      # Python-гейтвей: HTTP-парсер, auth, интеграция
node dsh-phone/web/test-md.js               # PWA-рендер: экранирование, markdown
node dsh-phone/web/test-items.js            # рендер элементов чата
node dsh-phone/web/test-draft.js            # синхронизация черновика
node dsh-phone/web/test-qr.js               # разбор QR-ссылки и автовход
cd dsh-phone-desktop/src-tauri && cargo test  # Rust-ядро: whitelist, allow_ip, token_eq, staging, QR, salvage конфига
cd dsh-phone/plugin/dsh-phone-bridge && npm test   # плагин: host-модули, web-половина, проводной протокол
node dsh-phone/plugin/dsh-phone-bridge/scripts/smoke-host-bridge.mjs   # интеграция моста: протокол, чтение, синк-фид
node dsh-phone/plugin/dsh-phone-bridge/scripts/smoke-host-write.mjs    # путь записи: отправка, апрувы, модели
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-plugin-channel.ps1  # HTTP-канал плагина на живом процессе узла
```

CI гоняет все наборы на каждый пуш и PR (`.github/workflows/ci.yml`), а `release.yml` повторяет их перед публикацией релиза - чтобы автообновление не развезло пользователям сломанную версию.

> Бинарники в `releases/` не подписаны (нет код-сининг-сертификата). Если SmartScreen ругается - это ожидаемо; собери из исходников сам, команда выше.
