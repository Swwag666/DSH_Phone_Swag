# DSH Phone - гайд по установке от и до

Цель гайда: после последнего шага телефон управляет сессиями DSH со стабильной связью, и ты знаешь, где чинить, если что-то отвалилось. Версия: **0.4.0** плюс unreleased-изменения в `main` (свой мост: плагин `dsh-phone-bridge` поднимает TCP-мост внутри DSH Desktop, поэтому Agents Anywhere больше не обязателен; узел ищет endpoint'ы по списку и держит HTTP-канал плагина как третий путь). Номер версии поднимается только вместе с релизом: тесты `updater_release` требуют совпадения версии в `tauri.conf.json`, в `releases/latest.example.json` и в trusted-comment подписи.

Схема такая: телефон → Tailscale → узел на твоём ПК (порт 8460) → мост в DSH Desktop (наш плагин `dsh-phone-bridge`, а если он не стоит - плагин Agents Anywhere). Четыре звена, каждое проверяется отдельно - гайд построен по этому принципу: поставил звено, проверил звено.

---

## 0. Что понадобится

| Компонент | Где взять | Зачем |
|-----------|-----------|-------|
| Windows 10/11 | уже есть | ПК-узел |
| [Tailscale](https://tailscale.com/download) | tailscale.com | приватный туннель ПК ↔ телефон |
| DeepSeek Harness Desktop | твой дистрибутив | сам агент |
| Плагин **dsh-phone-bridge** | `dsh-phone/plugin/dsh-phone-bridge` в этом репо | свой мост JSON-RPC + синхронизация черновика, рекомендуется |
| Плагин **Agents Anywhere** | включается в DSH Desktop | запасной мост JSON-RPC |
| `releases/dsh-phone-setup.exe` | из этого репо | узел |

Время: ~10 минут, если Tailscale уже стоит.

## 1. Tailscale на оба устройства

1. Поставь Tailscale на **ПК** ([tailscale.com/download](https://tailscale.com/download)), войди любым способом (Google/GitHub/Microsoft).
2. Поставь приложение Tailscale на **телефон** (App Store / Google Play), войди **тем же аккаунтом**.
3. На ПК выполни `tailscale ip -4` (или открой Tailscale из трея) - увидишь адрес вида `100.x.x.x`. Запиши его, это адрес твоего узла.

Проверка звена: на телефоне открой Tailscale, нажми на устройство ПК - должен пинговаться (в приложении есть ping). Не пингуется - перезапусти Tailscale на обоих, проверь что в одном аккаунте.

> Трафик внутри tailnet уже шифрован (WireGuard), поэтому plain HTTP между телефоном и узлом - норм. TLS включается позже, по желанию.

## 2. DSH Desktop + мост

Мост - это то, через что узел дёргает агента. Вариант A рекомендуется: наш
плагин не зависит от Agents Anywhere, не требует учётки и облака, и узел пробует
его первым. Вариант B пригодится, если свой плагин поставить нельзя.

Плагин один на две задачи: он же синхронизирует черновик поля ввода между
телефоном и DSH Desktop. Отдельного `dsh-draft-sync` больше нет - он влит в
`dsh-phone-bridge`.

### Вариант A (рекомендуется): свой плагин dsh-phone-bridge

1. Запусти DeepSeek Harness Desktop, залогинься и **закрой** его.
2. Скопируй папку `dsh-phone\plugin\dsh-phone-bridge` из этого репо в
   `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-phone-bridge\`.
3. В `%USERPROFILE%\.dsh\profiles\desktop\package.json` добавь строку
   `"dsh-phone-bridge"` в массив `dsh.profile.bundles`.
4. Запусти DSH Desktop.

Проверка звена: появился файл
`%USERPROFILE%\.dsh\dsh-phone\bridge\endpoint.json` - в нём адрес TCP-моста,
который узел читает при старте.

> Записи нет в lockfile профиля, поэтому любая команда вида
> `dsh plugin --profile desktop add ...` (или pnpm install в профиле) может
> снести папку - просто скопируй её заново из репо.

> Если раньше стоял отдельный плагин `dsh-draft-sync`, убери его: удали строку
> `"dsh-draft-sync"` из `dsh.profile.bundles` и папку
> `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-draft-sync\`. Иначе
> черновик ведут два движка сразу: лишний long-poll `/api/events`, второй
> MutationObserver на документ и риск эха. Объединённый плагин чужой движок
> замечает, уступает ему черновики и пишет предупреждение в консоль десктопа, но
> правильный вариант - старый удалить.

### Вариант B: плагин Agents Anywhere

1. Запусти DeepSeek Harness Desktop, залогинься.
2. Включи плагин **Agents Anywhere** (настройки → плагины).
3. Проверь, что появился файл `~/.dsh/agents-anywhere/bridge/endpoint.json`
   (в проводнике: `C:\Users\<ты>\.dsh\agents-anywhere\bridge\`).

Вход в учётку Agents Anywhere **не нужен** - узел стучится в локальный файл, не в облако.

### Как проверить, какая дверь открыта

После шага 3 (узел запущен) открой `http://127.0.0.1:8460/api/health`:

- `bridgeChannel: "tcp"` + `bridgeEndpoint` - TCP-мост поднят, в `bridgeEndpoint`
  видно, какой именно файл сработал (наш или AA);
- `bridgeChannel: "plugin"` - TCP-моста нет, но жива web-половина плагина:
  статус и события идут по HTTP, в `pluginBridge` видны очередь, rtt и возраст
  последнего пуша;
- `bridgeChannel: "none"` - не открыта ни одна дверь: проверь файлы
  `endpoint.json` и что DSH Desktop запущен.

## 3. Узел на ПК

### Установка

1. Скачай/собери `releases/dsh-phone-setup.exe`, запусти. Установщик создаст ярлыки в Пуске и на десктопе.
   - Портативный вариант: `releases/dsh-phone.exe` - один файл, положи куда хочешь, запусти.
   - **SmartScreen может ругнуться** на неподписанный бинарник («Система Windows защитила ваш компьютер») → «Подробнее» → «Выполнить в любом случае». Это ожидаемо: код-сининг-сертификата у проекта нет. Не хочешь жать - собери из исходников сам (`README.md` → «Сборка из исходников»).
2. Запусти DSH Phone. Окно минимизируется в трей (иконка рядом с часами), сервер поднимается на порту `8460` сразу.

### Конфиг и файрвол (один раз)

1. **Файрвол**: запусти `tools/fix-firewall.bat` **от администратора** (правый клик → «Запуск от имени администратора»). Создаёт правило для входящего TCP 8460. Без него телефон до узла не достучится.
2. **IP-allowlist** (рекомендую сразу): открой `%APPDATA%\dsh-phone\config.json` и заполни:
   ```json
   "allowed_ips": ["100.64.0.0/10"]
   ```
   Это весь tailnet-диапазон Tailscale - телефон пройдёт, всё снаружи (Wi-Fi-соседи, LAN) - нет. Loopback разрешён всегда, так что локальные проверки не сломаются. Пустой список = пускать всех, узел при старте напечатает предупреждение в консоль.

### Проверка звена

На **ПК** открой в браузере: `http://127.0.0.1:8460/api/health`

Должен вернуться JSON вида:
```json
{"ok":true,"runtime":"rust","bridge":"connected","tailscale":"100.x.x.x","tls":"off","devices":[...]}
```

- `"ok":true` - узел жив.
- `"bridge":"connected"` - мост к DSH работает (если `disconnected` - см. траблшутинг, п.2).
- `tailscale` показывает твой `100.x.x.x`.

## 4. Подключение телефона

1. В окне DSH Phone найди карточку **«Ключ доступа»** - там токен (32 hex-символа). Скопируй его.
2. На телефоне (Tailscale включён!) открой браузер: `http://100.x.x.x:8460` - адрес из шага 1.
3. Введи токен на экране входа. Жми «Войти».
4. Сделай из страницы приложение: Safari → «Поделиться» → «На экран Домой»; Chrome → меню → «Установить приложение». Появится иконка, открывается на весь экран, история кэшируется - чат открывается мгновенно даже при слабой связи.

Аутентификация: токен передаётся заголовком `X-Dsh-Token` (в запросах и лонг-полле событий), сравнение constant-time, 10 промахов подряд = разрыв соединения. Плюс RPC-whitelist: телефон может звать только 18 фиксированных методов (16 моста + 2 локальных draft-метода `session.updateDraft`/`session.getDraft` - синхронизация черновика поля ввода между PWA-клиентами узла, в мост не уходят).

### Проверка финальная

На телефоне открой чат, отправь тестовое сообщение агенту. Пришёл ответ, стримится по буквам - всё, система работает целиком.

## 5. Опции по вкусу

| Что | Как |
|-----|-----|
| **TLS** (пиннинг + микрофон в Safari) | Включи тумблер TLS в конфиг-карточке узла. Серт самоподписанный с SAN на tailnet-IP; отпечаток sha256 показывается рядом - телефон предложит «доверять» при первом заходе на `https://100.x.x.x:8460` |
| **Автостарт** | Тумблер «Автостарт» в узле (пишет Run-ключ HKCU, стартует свёрнутым) |
| **Второе устройство** | Конфиг-карточка → «Устройства» → добавить: свой токен, свой коннектор, своё окно агента в DSH |
| **Срок жизни вложений** | `staging_retention_secs` в конфиге (по умолчанию 7 дней; узел подчищает старые файлы раз в час; 0 = только руками) |

## 6. Траблшутинг по звеньям

Диагностика всегда сверху вниз - сначала звено, которое ближе к телефону.

**Телефон не открывает `http://100.x.x.x:8460`**
1. Tailscale на телефоне включён? (забывают после перезагрузки)
2. `http://127.0.0.1:8460/api/health` на ПК открывается? Нет → узел не запущен.
3. Файрвол-правило есть? Перезапусти `tools/fix-firewall.bat` от админа.
4. `100.x.x.x` совпадает с тем, что показывает узел в окне? IP мог смениться.
5. Всё ок, но по-прежнему таймаут → WARP-конфликт, см. ниже.

**«Мост отключён» в интерфейсе / health показывает `bridgeChannel: "none"`**
1. DSH Desktop запущен и залогинен?
2. Открыта ли хоть одна дверь: `~/.dsh/dsh-phone/bridge/endpoint.json` (наш
   плагин) или `~/.dsh/agents-anywhere/bridge/endpoint.json` (AA)?
3. Наш плагин скопирован в профиль и перечислен в `dsh.profile.bundles`? После
   правки `package.json` профиля DSH Desktop надо перезапустить.
4. Перезапусти DSH Phone: узел переподключается при старте и перебирает оба
   endpoint'а по списку (наш первым).
5. `bridgeChannel: "plugin"` при установленном плагине означает, что его
   TCP-мост не поднялся (причина в логе DSH Desktop), но web-половина жива:
   статус и события идут по HTTP, а метрики видны в `pluginBridge`.

**Связь отвалилась после включения/выключения Cloudflare WARP** - WARP и Tailscale рвут друг другу сокеты. Кнопка **«Лечить связь»** в конфиг-карточке узла перевязывает сокеты (`debug rebind` + `restun`). Если часто повторяется - запусти `tools/fix-tailscale-warp.bat`: он пропишет в hosts актуальные адреса controlplane/login Tailscale (резолвит через 4 публичных DNS с консенсусом, бэкапит hosts перед записью; если резолв не сошёлся - файл не трогает).

**После обновления приложения** - закрой страницу на телефоне и открой заново (PWA обновляется со service worker-задержкой; текущая версия кэша видна в health).

**SmartScreen при установке** - «Подробнее» → «Выполнить в любом случае» (бинарник не подписан), либо пересборка из исходников.

**Проверить, что вообще происходит** - `http://100.x.x.x:8460/api/health` с телефона показывает: bridge-статус, uptime, счётчик запросов, IP-allowlist, список устройств. Это твоя панель диагностики в браузере.
